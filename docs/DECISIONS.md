# Implementation decisions

These choices were made within the instruction to build the complete product immediately.

| Choice                                                                                                                                          | Reason                                                                     | Cost if it needs changing                                                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| A separate `clientlane` repository and `build/clientlane` branch, without an additional worktree                                                | Preserve the earlier PricePilot project and work in an isolated checkout   | Two repositories to manage                                                                                            |
| Proceed from the written design without another approval pause                                                                                  | The user explicitly authorized building now                                | Rework if an assumed workflow differs from the desired product                                                        |
| Adapt development workflow commands for Windows                                                                                                 | This workspace uses Windows and PowerShell                                 | Those development orchestration commands need adaptation on other systems; application scripts use portable Node APIs |
| Collaborators can work on assigned projects and read their internal notes, while owner controls stay restricted                                 | Make collaboration useful without sharing the whole workspace              | Assigned-project notes are shared with that collaborator; stricter note permissions would need a new policy           |
| Upload and download through an authenticated application proxy on every request                                                                 | Recheck current project access and revocation before serving private files | Application bandwidth and an extra server hop                                                                         |
| Hash portal tokens and keep an authenticated encrypted copy for invitation/reminder links, using a server-only key derived from the jobs secret | Support later email delivery without storing plaintext bearer tokens       | Losing or rotating that encryption secret requires replacing existing portal links                                    |
| Check reminder eligibility immediately before SMTP delivery and use leased, deduplicated, retryable queue records                               | Stop ordinary duplicate jobs and avoid chasing completed or revoked work   | SMTP acceptance can be ambiguous, so a crash or connection failure can still cause a duplicate email                  |
| Prepare public marketing independently while the backend implementer worked on separate files                                                   | Make useful progress without conflicting application changes               | Extra coordination and final integration checks                                                                       |
| Use Clientlane as a working product name                                                                                                        | Give the application a coherent identity during implementation             | Domain and trademark clearance may require renaming before launch                                                     |

The overview initially shows ten items per group, with accurate totals and controls to reveal more. This keeps Today usable for freelancers managing many projects and preserves access to later upcoming work. The cost is an extra click to inspect longer lists.

Local setup preserves manually configured encryption keys when their dotenv representation is safe. It refuses to rewrite keys requiring escaping or variable expansion, before touching the environment file. The cost is keeping such an environment manually; generated hexadecimal keys work normally.

New projects start under the owner's management. Teammates receive explicit access to that project before assignment, and edit forms offer only teammates with current access. This preserves the project's permission boundary. The cost is an extra grant step; assigning during creation would need a future atomic permission-and-creation operation.

The local build does not collect payments or deploy publicly. Hosted authentication/email/scheduling and launch prerequisites are described in the README. The full verification record is in VALIDATION.md.

The product walkthrough is a silent, captioned recording of an isolated real local project, with a readable transcript and chapter guide. This explains the workflow without requiring an account. The cost is no spoken narration; captions and full-screen playback support viewing.

Extra-work prices remain owner-only as specified. Collaborators may deliver assigned project work, while publishing a binding quote requires the studio owner. The cost is an owner approval step; future explicit pricing permissions could broaden this intentionally.
