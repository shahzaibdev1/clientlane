# Clientlane design

The user authorizes immediate execution, all previously discussed workflows, Next.js + Supabase, extensive tests, readable polished UI, SEO and marketability. No payment processing, provider setup, publishing or external outreach. Design/plan confirmation is waived by the user's explicit instruction to build now.

## Product

Clientlane (working name; trademark/domain availability not established) helps independent web/design freelancers and small agencies run multiple client projects. Owner dashboard and a radically simple client portal. No claims of being market-leading or measured time savings without evidence.

## Complete workflow

- Account signup, confirmation, login, logout, recovery/password reset. Protected server-rendered app, Supabase sessions refreshed. Local confirmation off only for development; hosted requires SMTP, confirmation, rate limits/CAPTCHA configuration.
- Workspace brand name/color/logo URL, freelancer or optional collaborators. One owner workspace; invitation by email, authenticated contractor accepts, project-scoped access, internal notes never visible to clients. Owner can revoke.
- Clients: name/email/company; projects: title/client/description/due date/status/assignee/revision allowance. Projects CRUD, archive/unarchive; retain records and explicit deletion confirmation. Search, filter, populated sample demo separated from real account.
- Project templates for web design, branding, retainer; owner saves custom reusable requests/milestones template; import active projects via validated CSV preview. Global overview Today/Waiting/Upcoming with concrete next actions, due dates, search.
- Client requests: title/instructions/type(text/file)/due; received/rejected/reopened. Missing-input list; client submits response/upload. Per-request reminder schedule; pauses and stops when received/archived/access revoked. Weekly digest one email per client aggregating open work. Track delay from outstanding due request; propose new deadline, client accepts, original deadline not silently changed.
- Deliveries: immutable versions per deliverable, note/file or HTTPS external link, feedback per version, client approval/changes decision plus actor/time. Revision rounds counted on needs-changes decision once per version; included/used/remaining shown. Extra change requests by client, owner quote in integer cents/currency with deadline, client acceptance/rejection; no payment collection.
- Private uploads/downloads via Supabase Storage signed URLs, type/size validation max20MB each, tenant/project paths, no executable HTML/SVG accepted, members/client grants checked server side. External links HTTPS only. Client portal expiring revocable random token emailed securely; no login needed for recipient. Bearer link grants limited access to one project, never owner workspace or internal notes. Hash token at rest; never expose broad service credentials. Token invitation preview/send link, owner rotation.
- Portal client sees Your next action / Review work / Files, milestones progress and agreements, client feedback and uploads. No team setup required. Team controls optional. Readonly handover assembled from approved latest versions/milestones/agreement history and export. Owner CSV export archive; secure account data export.
- Actual email invitations/reminders/weekly digest via SMTP configured env and authenticated scheduled route. Local Mailpit test transport; hosted scheduler+SMTP described. Queue idempotency/locking and retry on failure, no emails to real recipients during tests. SMTP unconfigured must yield explicit setup error, no false sent indicators.
- Branded demo no signup, persistent local storage with reset. All primary workflows usable in demo; email and upload clearly marked local preview. Public revision allowance tracker free utility with copy/download and CTA.
- Marketing home: truthful positioning, product illustration in HTML, interactive/demo CTA, FAQ, feature/usage routes, 3 practical original guides, transparent no payment required signup, no fabricated testimonials/prices or legal assertions. Metadata/canonical/OpenGraph, robots/sitemap, semantic headings, descriptive routes, FAQ and SoftwareApplication structured data without invented rating. App/auth/portal/demo noindex and absent from sitemap.
- Accessibility: semantic buttons/forms/labels, keyboard dialogs/focus, visible focus, errors and success feedback, contrast, responsive mobile layouts. No horizontal scrolling at375px. Loading/error/empty states. Never expose backend/debug jargon in user-facing flow.

## Architecture & limits

Next16 App Router React TypeScript; Supabase Postgres/Auth/Storage. State aggregates in workspace JSONB with optimistic version for domain transactions; dedicated member, project-access and portal-grant/outbox tables for access control/notifications. Mutations server-only through validated commands. Critical DB RPC permissions revoke direct writes, row-level ownership checks; atomic compare-and-save. Clients limited to projected public data and narrow commands under hashed grants. Service-role used on server only for authorized portal operations/storage/email jobs after explicit checks; never in client bundle. Contractor memberships constrained to assigned project scopes and public-to-team data. Max200 clients,500 projects,200 requests/project,100 deliveries/project,50 versions/delivery,200 comments/version,500 events/project, state10MB. Reject rather than silently truncate. UTC date-only deadlines; safe currency formatting, USD/EUR/GBP/PKR/CAD/AUD. File content is opaque, never interpreted; external integrations through HTTPS links rather than claiming sync. No accounting/video editing/native apps/AI/social publishing/live marketplace integration; portal supplements existing marketplace processes, not moving payments.
