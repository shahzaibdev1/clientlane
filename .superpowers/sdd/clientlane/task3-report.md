# Task 3 product UI implementation report

Implementation scope: authenticated workspace, authentication and recovery, bearer client portal, project team invitation, and persistent interactive demo. Public marketing, global fallbacks, package/configuration/scripts, and release tests remain root-owned. Implemented against the actual domain schemas/commands, `WorkspaceView`, and Task 2 server actions; no alternate backend or weakened authorization was added.

## Delivered behavior

- Warm canvas, navy navigation, teal controls, readable cards, mobile navigation and project tabs; separate `workspace.css`. Desktop and 375px screenshots are `docs/screenshots/workspace.png` and `workspace-mobile.png`. Mobile axe checks pass. Native labelled dialogs support Escape and restore trigger focus; invalid dialog submissions retain inputs and focus visible errors.
- Real signup, login, logout, account confirmation messaging, forgot-password email, callback error messaging and reset-password forms. Safe internal return paths preserve team invitation destinations. Private/auth/demo/portal metadata is noindex and no-referrer; proxy matcher includes the new signup, forgot-password and demo routes. Browser/server/proxy Supabase cookie options share URL-normalized Secure configuration: HTTPS including uppercase protocol/whitespace is secure; local HTTP remains usable. Default browser-readable cookie behavior is preserved.
- Today shows actionable due/waiting/upcoming groups, real totals and initial ten items per group with Show more controls. Project/client search and project status filtering, empty-state create controls and optional sample import are usable. Sidebar scroll preserves logout with long account emails. Clients create/edit/delete with domain-blocked deletion when projects exist. Projects create/edit/status/due date/revision allowance/member assignment, archive/restore and confirmed deletion use actual commands.
- Project Overview, Requests, Deliveries, Agreements, private Notes and Handover tabs share one board. Milestones create/edit/complete/delete. Requests include type, instructions, due date and reminder configuration; client text/file responses, history, reject reason, reopen and delete controls. Received/archived/completed reminders explicitly show their paused reason. Response history remains available after reopen, including a single previous submission.
- Delivery first/new versions contain title, note and real uploaded file references or HTTPS links. Versions can be selected; team feedback and client decisions remain tied to the correct version. Latest-only client approve/needs-changes controls expose included/used/remaining revisions; old versions are read-only. Actor UUIDs resolve to project team labels rather than leaking raw IDs into normal author copy. Owner workspace does not expose client approvals; clearly labelled demo client preview uses the actual client actor.
- Actual private file uploads use `/api/files`, the existing 20MB limit and server-authorized references. Pending references can be removed before submit. Download links use the existing authorized proxy. Upload help explains ZIP for source/SVG deliverables or HTTPS links. Demo attachments are explicitly HTTPS previews and never invent storage paths or call upload services.
- Client extra change requests, team quotes with exact integer cents, currency, due date and note, client accept/decline; deadline proposals with reason/current/new date and client accept/decline. Acceptance records agreement without collecting payment. Exact decimal parsing avoids floating-point rounding, including the safe integer boundary.
- Owner secure link create/rotate/expiry/copy/open/send/revoke controls bind to real server actions. SMTP success is described as acceptance by the email server. Old rotated/revoked links render a friendly unavailable state. Portal receives only projected public project data, supports client responses/review/agreements and private authorized files, and retains draft forms when stale updates reload the latest snapshot.
- Team invite email and selected project scopes, exact authenticated `/app/invite/[token]` acceptance route, owner active/pending list, refresh/revoke and member assignment. Invited workspace selector enters the actual member scope; member view omits owner settings/client/template controls and only displays authorized projects.
- Three built-in templates plus save-from-project custom templates; custom rename/description/revision allowance and confirmed deletion. New project template selection creates actual requests/milestones. CSV sample download, pasted/file input, domain validation and all-row preview feed the atomic import command. Project CSV and workspace JSON exports are real downloads. Handover exports public project fields, milestones/agreements and only latest approved delivery versions; no private notes/client requests are included.
- Brand name/color/HTTPS logo/currency and weekly digest settings bind to the real settings command. Owner email activity uses `listEmailQueue` and errored message retry uses `retryEmail`; demo email copy is explicitly preview-only.
- Demo strictly parses a versioned workspace envelope from local storage and uses `sampleState(todayUTC)` plus `applyCommand` with the same owner/client actors as production. Reset is confirmed and advances the generation. Cross-tab stale forms preserve inputs and reject the first conflicting write; retry uses current state. Corrupt storage gives a reset route. No demo interaction sends email or invokes production mutation actions.

## Self-review and limits

Reviewed role-gated controls, public/private projections, strict command arguments, exact amounts/UTC dates, current state references, native form accessibility and the complete Task 3 brief. No brief workflow is intentionally omitted. Browser tests cover representative commands rather than every possible delete/edit/error permutation. Backend tests remain the authorization boundary for members and client tokens; hiding controls is additional UI behavior, not the permission mechanism.

Real recovery, signup, SMTP and files are verified only against the isolated local services. Hosted HTTPS Secure behavior is configuration-unit verified, not a remote deployment check. Pending uploaded reference removal intentionally removes the form reference; the existing backend provides no unattached-object delete action, so it does not claim immediate storage deletion. Self-review identified transport rejection handling in owner initial team/email loads and the portal's explicit reload promise; both now catch exceptions, show connection/retry copy and avoid leaving busy state active. These narrow catches were source-reviewed and statically checked; no distinct browser offline-injection scenario was added. Validation exceptions from strict schemas can expose detailed Zod messages rather than tailored prose in uncommon malformed-input cases. This is an explicit review concern, not silently claimed coverage.

One dev Turbopack aggregation panic (`aggregation_update.rs:2048`, missing HMR upper/follower edges) happened while files were changing during an earlier run. The process was stopped and restarted; subsequent stable-source runs did not reproduce it. The focused passing recovery run logged Next aborted/ECONNRESET requests during full browser navigations, including dev-server uncaughtException logging; it completed successfully without a panic or restart. No package/webpack change was made. Root owns the independent review, final production build and complete production browser/release gate. No deploy, payments, hosted mail or external outreach occurred.
